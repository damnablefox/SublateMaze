# ADR-0006：暂不替换 FTS5 为 Tantivy

- 状态：接受
- 日期：2026-10-22

## 背景

方案原计划在 M5 用 Tantivy 替换 SQLite FTS5，以获得 BM25 排序与更大规模。当前实现已对中文逐字切分，用短语匹配页码级检索，并与 LanceDB 向量通过 RRF 融合。

## 决策

M5 保留 FTS5，暂不引入 Tantivy。原因：

1. Tantivy 需要新的 Rust 依赖与中文分词器（如 jieba/n-gram），构建体积与 CI 时间增加；
2. 索引写入目前由 `storage-sqlite` 维护，迁移到原生层会改变导入链路与故障边界；
3. 现有规模下的检索质量与延迟尚未暴露问题，先通过基准与真实教材抽样验证再决定。

## 影响

- `ctx.search` 接口不变，未来替换只影响全文索引实现；
- 需要新增 `docs/specs` 基准与真实教材抽样结论后，再启动替换；
- 若替换，必须保留无向量服务时纯全文检索的降级路径。
