# ADR-0002：Rust 原生层的边界

- 状态：已采纳
- 日期：2026-10-21

## 背景

项目要求 Rust 提供底层性能，但 Electron 主进程已经是 Node 运行时。若让 Rust 承担全部数据访问，会引入跨语言所有权、异步与打包复杂度。

## 决策

- Rust 通过 napi-rs 以原生插件形式接入，注册为 `ctx.native` 服务；
- Rust 只承担无状态或可重建的 CPU 密集任务：文件哈希、PDF 文本提取、全文索引、批量计算；
- **SQLite 与 LanceDB 的写入仍由 TypeScript 插件负责**，Rust 不直接打开业务数据库；
- 原生模块缺失时，`native` 服务降级为 TypeScript 实现，业务流程不中断；
- 大文件以路径传递，不把整本书序列化跨语言边界。

## 后果

- 保持单一写者与数据一致性；
- 原生模块需要按 Electron ABI 构建并 `asarUnpack`；
- 性能收益集中在解析与索引，业务调用没有额外语言切换成本。
