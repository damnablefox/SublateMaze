# Spec-0014：向量检索基准与扩展决策

- 状态：已完成
- 日期：2026-10-22
- 里程碑：M5（第四阶段）

## 目标

1. 提供可重复的 10 万级向量写入与查询基准，不依赖 AI Key 或真实 embedding；
2. 记录写入与查询的 P50 / P95，作为后续优化基线；
3. 明确本阶段对 Tantivy 替换 FTS5、UI slot 机制的决策与理由。

## 非目标

- 不在本阶段替换 FTS5；
- 不引入 Tantivy 或新的中文分词依赖；
- 不实现插件向渲染端注入 React 组件；
- 基准不进入 CI（耗时与磁盘占用较大），按需手动运行。

## 实现

新增 `scripts/bench-vector.ts`：

```powershell
pnpm bench:vector -- --rows 100000 --dim 1024 --batch 5000 --queries 50
```

- 使用临时目录与临时 LanceDB collection，结束时清理；
- 向量由确定性伪随机函数生成，避免网络与模型依赖；
- 按 `batch` 条一批写入，模拟多个载体的批量重建；
- 查询使用随机向量 topK=10，统计 P50/P95；
- 输出 JSON：行数、维度、写入批次数、写入 P50/P95、查询 P50/P95、总耗时。

## 决策

### Tantivy

沿用 SQLite FTS5，本阶段不替换：

- 当前 FTS5 对中文按字切分并以短语匹配，已满足页码级检索与混合检索；
- Tantivy 需要额外 Rust 依赖与中文分词器，索引同步链路要从 `storage-sqlite` 迁移到原生层；
- 替换收益（BM25、规模）在 10 万页规模内不明确，先以基准与真实教材抽样决定。

### UI slot

本阶段不实现通用 UI slot：

- 渲染端只加载内置页面，插件不提供可执行前端代码，避免供应链与权限风险；
- 插件已可通过 IPC 提供数据与操作，页面入口内置在侧边栏；
- 后续如需扩展，采用「页面注册表 + 命令面板」而非任意组件注入。

详见 `docs/adr/0006-defer-tantivy.md` 与 `docs/adr/0007-defer-ui-slots.md`。

## 验收标准

- 基准脚本可在无 AI Key 环境运行，结束后清理临时目录；
- 输出包含写入与查询的 P50/P95；
- `pnpm typecheck`、`pnpm lint`、`pnpm test` 通过，基准脚本不影响现有测试；
- 10 万条 1024 维数据完成写入与查询，记录实测结果。

## 实测结果

环境：Windows x64、Node 24、LanceDB 0.40.0、`dim = 1024`、`rows = 100000`、`batch = 5000`、`queries = 50`、`topK = 10`。

| 指标 | 数值 |
|---|---|
| 表行数 | 100000 |
| 写入批次数 | 20 |
| 写入 P50 | 985.2 ms |
| 写入 P95 | 1089.7 ms |
| 写入总耗时 | 20964.9 ms |
| 查询 P50 | 535.2 ms |
| 查询 P95 | 652.7 ms |
| 查询总耗时 | 26287.5 ms |
| 总耗时 | 47252.4 ms |

结论：

- 批量写入 10 万条 1024 维向量约 21 秒，单批 5000 条约 1 秒，可支撑全库重建；
- 查询为未建 ANN 索引的暴力扫描基线，10 万级 P95 约 653 ms；
- 后续若真实教材全库达到 10 万 chunk，应在 `storage-lancedb` 增加 `IVF_PQ` 索引（`Index.ivfPq`）并重新跑基准，比较召回率与延迟；
- 小规模（1000 条 128 维）基线：写入 P95 103.4 ms、查询 P95 45 ms，脚本本身工作正常。
